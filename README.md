# linuxdo-auto-reader

linux.do（以及其它 Discourse 论坛）的自动阅读用户脚本：按设定节奏自动翻帖，每篇帖子停留一段时间后换下一篇，支持多标签页各自独立启停，可选给高赞楼层自动点赞。

作者 liuweiqing。2.x 是在这个仓库里重新整理过的版本；更早的 1.4.x 是同一作者发布在 Greasy Fork 上的原始版本。

> [!WARNING]
> linux.do 的服务条款明确禁止使用插件或脚本自动访问论坛。使用本脚本存在账号被风控或封禁的风险，请自行评估并保持低速使用。

## 功能

- **自动逐篇阅读**：从论坛的 /latest.json 取候选帖（跳过评论数 ≥ 1000 的帖子，每轮最多准备 60 篇），读完一篇休息 5 秒再换下一篇。
- **每贴限时**：默认每篇随机停留 15~30 秒（可在设置里改），到点直接换下一篇，不必把整帖翻到底；也可以选「完整阅读」模式滚到帖底再换。
- **四档阅读节奏**：保守 / 标准 / 快速（标准 2×）/ 极速（标准 3×）。步长、滚动间隔、检查频率、跳转间隔一起变，档位越低越像人工。
- **防卡死**：只用一条定时器链驱动滚动，不会用 setInterval 反复打断页面；连续几次没有滚动进展就先推到底部触发懒加载，仍然没有进展且已经读够时长，就判定本贴读完直接换下一篇。
- **主动限流**：请求之间、跳转之间都有硬性最小间隔；列表最多抓 2 页；遇到 429 或连续错误按 15 秒 → 60 秒 → 300 秒指数退避。
- **多标签页各自独立**：每个标签页有自己的「开始/停止阅读」和「自动点赞」开关，在 A 标签页点停止不会影响 B；刷新页面接着跑，复制出来的标签页会自动换成新号并按新标签页处理。已读帖数、今日帖数、点赞次数、待读队列、点赞额度则是全局共享的，不会随标签页变多而重复计数、重复请求。
- **自动点赞（默认关闭）**：只给点赞数超过阈值（默认 30）且自己还没赞过的楼层点赞，点的是楼层里真正的点赞按钮；每轮最多 3 个，间隔 4~9 秒随机，过去 24 小时最多 50 次（可调，0 表示暂停）。
- **悬浮摘要卡片**：左下角显示已读帖数 / 今日帖数 / 本页标签号 / 其它正在运行的标签页数量 / 累计楼层 / 当前状态；点卡片展开设置，卡片本身可以从卡片以外的区域拖到别处，位置会记住。
- **每日上限与夜间静默**：默认每天最多 150 帖、夜间不静默。

脚本不向任何第三方服务器上报数据：设置、计数、点赞记录都只写在浏览器本地（localStorage / sessionStorage），网络请求只发给当前所在的论坛。

## 安装

1. 先给浏览器装一个用户脚本管理器：[Tampermonkey](https://www.tampermonkey.net/)。Edge、Chrome、Firefox 都可以。
2. 安装脚本，两种方式任选：
   - 到 [Releases](https://github.com/wssfk12138/linuxdo-auto-reader/releases) 页面下载最新版的 `auto-read.user.js`，拖进浏览器或直接打开。
   - 或者从 main 分支直接安装：https://raw.githubusercontent.com/wssfk12138/linuxdo-auto-reader/main/dist/auto-read.user.js
   Tampermonkey 会弹出安装页，点「安装」。
3. 打开 linux.do，左下角会出现悬浮卡片，点「开始阅读」。

脚本生效的站点：linux.do、meta.discourse.org、meta.appinn.net、community.openai.com、idcflare.com。

## 使用

- 卡片上的「开始阅读 / 停止阅读」只作用于当前标签页，别的标签页不受影响。
- 点卡片展开设置面板，改完即时生效。
- 卡片可以用鼠标从卡片以外的区域拖动，刷新后位置还在。
- 想彻底停掉：在卡片上点「停止阅读」，或者到 Tampermonkey 里禁用脚本。

### 设置项

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 阅读模式 | 按时间阅读 | 「按时间阅读」到停够时间就换下一篇；「完整阅读」把整帖滚动到底再换 |
| 阅读速度 | 标准 | 保守（更慢）/ 标准 / 快速（标准 2×）/ 极速（标准 3×） |
| 每日上限（帖，0=不限） | 150 | 当天读完这么多帖后自动停止阅读 |
| 每贴最长停留（秒） | 30 | 与下面的下限组成区间，每篇在这个区间里随机取一个停留时长 |
| 每贴最少阅读（秒） | 15 | 下限填得比上限还大时，上限会被自动抬起来 |
| 只赞超过 N 赞的楼层 | 30 | 自动点赞的点赞数阈值 |
| 过去 24 小时点赞上限（次，0=暂停） | 50 | 到额度后自动点赞暂停并显示原因，额度恢复后继续 |
| 00:00-07:00 暂停 | 关 | 夜间静默 |
| 新标签页自动开始阅读 | 关 | 关着的时候新标签页默认是停止状态 |

## 从源码构建

脚本本身没有依赖、不需要打包器，`src/auto-read.user.js` 就是可以直接安装的完整用户脚本。`dist/auto-read.user.js` 是同一份内容的构建产物，供直接安装和 Release 使用。

```bash
npm run build   # 校验 @version 与 package.json 一致、做语法检查，然后生成 dist/auto-read.user.js
npm test        # 回归测试，自带 DOM / XHR / localStorage 仿真，不需要真实浏览器
```

发布新版本：

1. 改 `src/auto-read.user.js` 的 `@version` 和 `package.json` 的 `version`，两者必须一致。
2. 提交之后打 tag 并推送：`git tag v2.3.6 && git push origin v2.3.6`
3. GitHub Actions 会跑构建和测试，然后创建对应的 Release，并把 `dist/auto-read.user.js` 作为附件传上去。

## 项目结构

```
src/auto-read.user.js      用户脚本源码，同时就是可直接安装的成品
dist/auto-read.user.js     构建产物，Release 附件
tests/auto-read.test.js    回归测试
tools/build.js             构建脚本
.github/workflows/         打 tag 时自动发布 Release
```
